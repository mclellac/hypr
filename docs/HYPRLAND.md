# Hyprland Configuration Documentation

This document describes the Hyprland configuration structure.

## Overview: A Generated, Modular Configuration

The Hyprland configuration is generated by the project's templating engine. The main entry point, `~/.config/hypr/hyprland.lua`, is kept minimal and acts as a loader that safe-requires other generated Lua modules.

This modular approach allows the system to manage default settings and themes while providing dedicated files for user customizations.

**You should not directly edit the main `hyprland.lua` or most of the files it requires, as they are overwritten when the configuration is regenerated.**

### Hyprland 0.54+ / v0.55+ (Lua)

The project leverages Hyprland's native Lua configuration support (v0.55.0+). Due to layout changes in Hyprland 0.54+, native `movefocus` and `movewindow` dispatchers are no longer used for directional arrow keys. `mainMod + arrow keys` use `exec, hypr-vim-nav l/r/u/d` to focus windows, and `mainMod SHIFT + arrow keys` use `swapwindow` to move them while preserving layout sizes.

## File Structure

The main `hyprland.lua` loads modules in a specific order:

**Core Configs**: Generated Lua modules for different aspects of the system.
    - `autostart.lua`: For applications that run on startup.
    - `envs.lua`: Environment variables.
    - `monitors.lua`: Monitor and display configuration.
    - `input.lua`: Mouse and keyboard settings.
    - `looknfeel.lua`: Gaps, borders, shadows, blur, and animations.
    - `windows.lua`: Window rules and behaviors.
**Keybindings**:
    - `bindings.lua`: **Generated file containing all keybindings.** Do not edit directly.
**Plugins**:
    - `plugins.lua`: **Generated file containing Hyprland plugin configurations (`hl.plugin`).** Managed via `theme.yaml`/`settings.yaml` and `hypr-plugin`.
**Application Tweaks**:
    - `apps.lua`: Loads application-specific rules from `~/.config/hypr/apps/*.lua`.

## How to Customize Hyprland

The primary way to customize your setup is by editing the `theme.yaml` file of your active theme.

### General Settings (`theme.yaml`)

For changes related to appearance, behavior, or variables used by the theme, you should modify your theme's `theme.yaml`.

The templating engine will take values from this file and place them in the correct generated configuration files.

### Example: Add a window rule and change gaps

```yaml
# theme.yaml
hypr:
  # Add a new window rule
  windowrule:
    - "float, ^(pavucontrol)$"
    - "size 800 600, ^(pavucontrol)$"

# Override a layout setting
layout:
  gaps_in: 8
  gaps_out: 15
```

After saving, re-apply your theme (`hypr-theme-set <theme-name>`) to see the changes.

### Keybindings

Keybindings are centrally managed and completely data-driven. The legacy system of static `.conf` files and `user_bindings.conf` overrides has been removed.

- **Storage**: All keybindings (defaults and customs) reside in the `keybindings` JSON array within the configuration models (`defaults.yaml` and `theme.yaml`).
- **Editing**: Use the **Keybindings Editor** (`hypr-keybindings-editor`). The editor manipulates this configuration array directly—creating, replacing, and removing items without appending override configurations.
- **Generation**: `bindings.lua` is dynamically compiled by the Jinja template engine by iterating over the `theme.keybindings` configuration.

Do not edit `~/.config/hypr/bindings.lua` manually. Any manual edits will be wiped upon the next theme change or config regeneration.
